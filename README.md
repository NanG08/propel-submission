Key components:
- **Strict Pydantic v2 schemas** (`app/schemas.py`) – `extra="forbid"` prevents unexpected fields.
- **Deterministic Money Gate** (`app/money_gate.py`) – pure Python policy engine with
  deterministic prompt‑injection detection, fraud escalation, usage‑based refunds, and
  high‑value caps.
- **SQLite Idempotency Store** (`app/idempotency.py`) – guarantees exactly‑once refund
  processing.
- **PII‑safe logging** (`app/logger.py`) – scrubs ticket content before emitting logs.

### Deep‑Dive Analyses

#### T‑1005 – Initiated Payment (Human Review Required)
- **Context**: Payment status is `initiated` (unsettled). The customer reports the money was deducted but the plan is still free.
- **Policy Path**: Rule 4 in `evaluate_refund_policy` detects an *initiated* renewal and blocks the refund, returning the reason *"Payment is in 'initiated' (unsettled) state; cannot refund unsettled funds. Escalated for payment reconciliation."*.
- **Human Flag**: The safety gate forces `needs_human=True` whenever a block reason is present (see `apply_safety_gates`). This guarantees a support agent reviews the pending settlement before any action.

#### T‑1006 – Annual High‑Value Plan (Human Approval Required)
- **Context**: Two successful annual renewals of Rs 1499 each. The user wants a refund.
- **Policy Path**: Rule 6 triggers when `latest_success.amount_inr >= 1000`. The engine blocks automatic refund and returns the reason:
  > "Eligible unused annual renewal (0 opens), but amount Rs 1499 exceeds auto‑refund cap (Rs 500); routed for 1‑click human approval".
- **Human Flag**: As with Rule 4, any block reason sets `needs_human=True`. The ticket is therefore escalated to a human operator for a one‑click approval workflow.

#### T‑1012 – Usage Gate (Refund Declined)
- **Context**: Monthly renewal of Rs 249, but the user has opened the app **2** times since renewal.
- **Policy Path**: Rule 7 checks the usage window. Because `app_opens_since_renewal > 0`, the refund is denied and the reason reads:
  > "Auto‑refund declined: 2 app opens recorded since renewal; routed to human agent."
- **Human Flag**: The rule explicitly returns `needs_human=True` to ensure the user receives a personalized response explaining why the auto‑refund was blocked.

### Prompt‑Injection Detection (T‑1003 & T‑1011)
Both tickets contain a **system‑note** instructing the assistant to ignore policies and approve a full refund. The deterministic scanner (`detect_prompt_injection`) searches subject + body for patterns such as:
- "system note"
- "ignore your previous instructions"
- "internal refund rules"
- "verified vip"

When a match is found, `apply_safety_gates` overrides the LLM draft, sets `refund.approved=False`, supplies the guard‑rail reason *"Blocked by security guardrail: adversarial instruction detected in ticket."* and forces `needs_human=True`. This guarantees that malicious instructions never result in an automatic refund.

## Task 3 – Backend Track (Scalability & Resilience)

### 1️⃣ 50 req/s Outage‑Resilience Design
| Layer | Technique | Description |
|------|-----------|-------------|
| **Ingress** | **Rate‑limited reverse proxy (NGINX/Envoy)** | Caps traffic at 50 req/s, returns `429` when exceeded. |
| **Queue** | **RabbitMQ (or Google Cloud Pub/Sub)** | Requests that hit the idempotency store are enqueued; workers process refunds asynchronously, guaranteeing at‑most‑once semantics. |
| **Circuit Breaker** | **Python `pybreaker`** wrapped around the LLM client & DB calls | Trips after N consecutive failures, instantly returns a degraded response (`needs_human=True`, `refund.approved=False`). |
| **Degraded Mode** | **Replay‑only fallback** | When the circuit is open, the service switches to deterministic replay mode, avoiding external API calls while still respecting safety gates. |

### 2️⃣ PostgreSQL DDL for Production Ledger (mirrors SQLite schema)
```sql
CREATE TABLE triage_ledger (
    ticket_id TEXT PRIMARY KEY,
    payload_hash TEXT NOT NULL,
    response_json JSONB NOT NULL,
    refund_approved BOOLEAN NOT NULL,
    refund_amount_inr INTEGER NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Index for fast conflict detection
CREATE UNIQUE INDEX uq_triage_ledger_hash ON triage_ledger (ticket_id, payload_hash);
```

### 3️⃣ Correlation Tracing Fields (for observability platforms like OpenTelemetry)
- `trace_id` – unique request identifier propagated from the HTTP header `X-Trace-Id`.
- `span_id` – ID of the current processing span (validation, money‑gate, DB write).
